# Companion.energy: dashboard prototype

A prototype for the Companion.energy contract management case. The reasoning behind it (problem,
alternatives, decisions) is in the accompanying document; this README covers what the code does and
how to run it.

## Running it

### With Docker (no Node needed)

**Production build**, served by nginx on <http://localhost:8080>:

```bash
docker compose up --build
```

**Dev server with hot reload** on <http://localhost:5173>:

```bash
docker compose up --build -V dev
```

The dev server mounts the source folder into the container, so edits apply immediately. Its
`node_modules` lives in a separate Docker volume; `-V` recreates that volume, so a dependency added
since the last run is installed. The production build does not reload: rebuild it with `--build`
to see changes.

Stop either one with `docker compose --profile dev down` (plain `down` skips the dev service).

### With Node

Requires Node 22.18+, which runs the TypeScript data script natively (see `.nvmrc`).

```bash
npm install
npm run dev
```

Then open <http://localhost:5173>.

## The problem

A first-time user has no clear picture of how their assets and their contracts fit together.
Control Room shows a diagram of the assets, Contracts lists the contracts, and nothing connects the
two. Nothing shows at a glance which sites are covered by a contract and which are not, and the
view does not scale to a customer with many sites.

## The solution

**Control Room** (the landing page) merges the two views around a map of the customer's sites.

- **Map:** each site shows what it is (industrial plant, warehouse, solar farm, ...) and a badge
  for one or several contracts; no badge means no contract. Nearby sites group into a counter that
  zooms in on press.
- **Site diagram:** selecting a site opens its grid connection and the assets behind it, with the
  number of contracts on the grid connection. The map shrinks to an embed in the corner and the
  selected site stays visible even when zoomed out.
- **Batteries:** the icon shows the charge (red, orange, green) and animates while charging; the
  card says Charging, Supplying or Standby, in plain words.

**Market Data, Futures** is a smaller proposition: the 18 overlapping lines become one small chart
per delivery product on a shared scale, each drawn as an off-peak to peak band with base inside,
with a single synced hover. Its filters (market, product length, profiles, trading days) live in
the URL, so a view can be shared.

## Mock data

There is no backend. The app reads JSON fixtures from `data/`, through a small `src/api/` layer
that stands in for the real API.

| File                    | What it holds                                               |
| ----------------------- | ----------------------------------------------------------- |
| `data/futures.json`     | Power futures prices, generated by a script (see below)     |
| `data/currentUser.json` | The signed-in user shown in the sidebar                     |
| `data/sites.json`       | 26 customer sites in Belgium, their assets and contract ids |

`data/futures.json` holds Belgian monthly, quarterly and yearly products, on every trading day
from June to September 2026. France is listed as a market but, as on the live dashboard, has no
futures data, so the page shows an empty state for it.

- Each day, all products of a market move with a shared shock plus their own noise, the way real
  futures react to the same news.
- Base is always the hour-weighted average of peak (60 weekday hours) and off-peak (108 hours),
  as on the market.
- The file is written by `npm run data:generate` (`scripts/generate-mock-futures.ts`). A fixed
  seed makes every run produce the same file, and a test fails if the file and the generator drift
  apart.

`src/api/futures.ts` validates the fixture once when it loads, then answers queries by market,
granularity and date range.

## Project structure

```
data/          JSON fixtures the app reads in place of an API
scripts/       Generator for data/futures.json
src/
  api/         Stands in for the backend: loads and validates the fixtures, answers queries
  app/         Layout, routes and the sidebar navigation config
  components/  Generic UI components (Sidebar, TabNav, Card, Select, MultiSelect, DateRangeStepper,
               ZoomControls)
  features/    Feature logic and UI: control-room/ (map, diagram), futures/ (chart, filters)
  lib/         Generic pure helpers and hooks
  pages/       One folder or file per page
  styles/      Design tokens and global styles
  test/        Test setup
```

## Stack

React 19, TypeScript, Vite, React Router, CSS Modules, Radix primitives and Lucide icons (the
building blocks of shadcn/ui), MapLibre GL with OpenFreeMap tiles (no API key needed), Vitest with
Testing Library, ESLint and Prettier. The site diagram uses React Flow.
